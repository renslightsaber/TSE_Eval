# ── B-2. ★★ DNSMOS 가 이 컨테이너에서 20배 이상 느려집니다 ★★
#    /proc/cpuinfo 는 호스트 224 core 를 보여주지만 cgroup cpuset 은 24개만 허용합니다.
#    speechmos 는 ONNX 세션을 ★ 옵션도 providers 도 없이 ★ 만듭니다:
#        speechmos/dnsmos.py:19-20  →  ort.InferenceSession(self.primary_model_path)
#    그래서 두 가지가 동시에 나빠집니다.
#      (1) onnxruntime 이 **호스트 토폴로지 기준**으로 스레드 풀을 잡고 각 스레드를 물리
#          코어에 핀하려다 실패 → 스레드마다 빨간 줄 + 심한 oversubscription:
#            [E:onnxruntime:Default, env.cc:234 ThreadMain] pthread_setaffinity_np failed
#      (2) providers 를 안 넘기면 onnxruntime 1.20 은 ★ CPU EP 만 ★ 씁니다 ([B-3]).
#
#    ★ 실측 (2026-08-06, 실제 PORTE-v3 오디오·평균 11초, TSE_Eval 파이프라인 end-to-end) ★
#      측정법: 60행 실행 − 20행 실행 의 한계비용/40 (고정 초기화 비용 상쇄),
#              DNSMOS 만 요청했으므로 행당 wav I/O 도 포함된 값입니다.
#
#        설정                                한계비용      15,000 utt   무가속 대비
#        ─────────────────────────────────   ───────────   ──────────   ─────────
#        무가속 (threads=0, CPU)             1475 ms/utt      369분        1.0배
#        intra_op=4 (CPU)                     550 ms/utt      137분        2.7배
#        intra_op=4 + CUDA  ← ★ 현재 기본     175 ms/utt       44분        8.4배
#
#      ※ CUDA 는 1회성 초기화 ~40초 추가 (5,000행 기준 0.5% 수준).
#      ※ `export OMP_NUM_THREADS=4` 는 효과가 없습니다 — onnxruntime 의 intra-op 풀은
#        OpenMP 가 아니라 자체 풀이라 SessionOptions 로만 제어됩니다(실측 확인).
#      ※ 점수 영향: CPU 설정끼리는 4e-07(사실상 동일),
#        CUDA 는 최대 ~3e-03 차이(부동소수점 커널 차이). DNSMOS 는 보통 소수점 2자리로
#        보고하므로 보고 정밀도보다 훨씬 작지만, ★ 세 프로젝트가 반드시 같은 EP 로
#        채점되어야 합니다 ★ — sidecar 에 requested/actual providers 가 기록됩니다.
#
#    ★ 이 가속은 TSE_Eval 에 이미 구현되어 있습니다 (tse_eval/ort_setup.py).
#      기본값이 CUDA 이며, CPU 로 되돌리려면 `--dnsmos-providers cpu` 를 쓰세요.

# ── B-3. onnxruntime-gpu 만 깔아두면 DNSMOS 는 CPU 로 돕니다 (해결됨)
#    "onnxruntime-gpu 를 깔았으니 GPU 로 돌겠지" 는 사실이 아닙니다. 실측 확인:
#        ort.InferenceSession(model)                       → ['CPUExecutionProvider']
#        ort.InferenceSession(model, providers=['CUDA...']) → ['CUDAExecutionProvider', 'CPU...']
#    즉 CUDA 로딩이 **실패하는 게 아니고**, onnxruntime 1.20 이 providers 미지정 시
#    CPU EP 만 쓰는 것이 정상 동작입니다(1.9+ 부터 명시 요구). speechmos 는 providers 를
#    넘기지 않으므로 CUDA 를 시도조차 하지 않습니다.
#    → TSE_Eval 은 `tse_eval/ort_setup.py` 가 providers 를 명시해 주므로 onnxruntime-gpu
#      핀이 실제로 값을 합니다(8.4배). 어떤 EP 로 돌았는지는 결과 옆 sidecar JSON 의
#      `dnsmos.actual_providers` 에서 확인하세요. 직접 확인은 [D-2] 스니펫.
#    참고: 이 머신은 시스템 cuDNN 9.4.0 + torch 번들 nvidia-cudnn-cu12 9.1.0.70 을 갖고 있어
#    onnxruntime-gpu 1.20.x (CUDA 12.x + cuDNN 9 요구) 조건을 충족합니다(위 실측이 그 증거).
