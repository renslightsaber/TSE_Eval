## 1. 이 실험의 목적

**단 하나를 검증한다 — `text_pooling` 을 논문 §V-C 로 정렬했을 때 성능이 달라지는가.**

논문 §V-C 는 텍스트 큐 임베딩을 *"averaging the outputs of the last four self-attention layers"*
로 만든다고 명시한다. v1 은 **마지막 1개 층의 last-token**(`last_layer`)으로 학습됐다
(팀원 코드 계승 — v1 report §2.2). 2026-08-07 에 코드를 정렬했으나 재학습은 하지 않았으므로,
**v1 의 수치는 논문 미정렬 조건에서 나온 것**이다. 이 실험이 그 공백을 메운다.

### 사전 예측 (2026-08-08, 학습 전에 기록)

| 예측 | 근거 |
|---|---|
| **차이는 작을 것 (±0.2 dB 이내)** | v1 가중치를 `last4_mean` 으로 강제 로드해 100 발화 추론 시 SI-SDR **6.14 → 6.21 dB (+0.07)**. 학습된 `proj` 통과 후 e_txt 코사인 **0.989** |
| order 실패는 **그대로일 것** | 원인이 pooling 이 아니라 **6초 crop**(두 화자 onset 포함 확률 2.3%)이기 때문 — v1 report §7.6 |

> 📌 예측을 **미리** 적어 두는 이유: 결과가 나온 뒤 "예상대로였다"고 사후 해석하는 것을 막기 위함.
> 예측이 빗나가면 그 자체가 중요한 발견이다.

## 2. v1 과 무엇이 다른가

### 2.1 학습에 영향을 주는 차이 — **단 하나**

`configs/config.yaml` 을 v1 스냅샷과 diff 한 결과(주석 제외):

| 항목 | v1 | **v2** | 근거 |
|---|---|---|---|
| `model.text_pooling` | (키 없음 → `last_layer` 폴백) | **`last4_mean`** | ★ 논문 §V-C |

**그 외 모든 학습 설정은 동일하다** — segment 6.0초 random crop, batch 8 × accum 5 (effective 40),
AdamW lr 1e-4, warmup 1000, clip 30, LoRA r16/α16, max_epochs 50, seed 2026, bf16.

### 2.2 학습에 영향을 주지 않는 차이

| 항목 | v1 | v2 | 영향 |
|---|---|---|---|
| `logging.ckpt_keep` | 3 | **10** | 파일 보관 정책 — 학습 궤적·gradient·RNG 무관 |

**왜 올렸나**: v1 은 `val/loss`(clamp(max=30) 적용값) 기준으로 best 를 골랐는데, 후반부에
`val/si_sdr` 과 최대 **0.93 dB** 어긋났다(v1 report §6.2). 실제 최고 성능은 **step 46,000**
(SI-SDR 7.150 / ESTOI 0.787)이었으나 `ckpt_keep: 3` 이 이미 지운 뒤라 **쓸 수 없었다.**
`val/si_sdr` 은 TensorBoard 에 500 step 마다 남으므로 체크포인트만 살아 있으면 **사후 재선정이 가능**하다.
10 = 마지막 5,000 step 커버 (13 GB × 10 = 130 GB, 디스크 여유 615 GB).

> ⚠️ **`val_max_batches` 는 50 그대로 두었다.** 500 으로 올리면 표본이 dev 의 1% → 10% 로 좋아지지만,
> v1 실측 발화당 1.27초 기준 **+17.6시간**(43 → 61시간, +40%)이고 v1 과 validation 조건이 달라져
> 이번 실험의 목적인 **단일 변수 비교가 흐려진다.** 개선은 v3 과제로 유지 (v1 report §8-3).

### 2.3 여전히 논문과 어긋나는 것 (v1 과 동일)

이번 실험이 **고치지 않는** 항목 — 결과 서술 시 반드시 유지해야 한다:

| 항목 | 논문 | v2 | 비고 |
|---|---|---|---|
| segment | 6초 mixture **합성**(§V-A, overlap 40~70%) | 6초 random **crop** | 숫자는 같지만 **성질이 다르다.** 논문은 crop 을 하지 않는다 |
| overlap 분포 | 40~70% | PORTE-v3 0~100% 균등 (논문 범위는 33.3%) | 데이터셋 결정 |
| sample rate | 16 kHz | **24 kHz** | ★ 의도적 — TPEX/PORTE-v3 정렬 |
| `max_epochs` · `early_stop` · `weight_decay` · `crop_mode` | **미명시** | 50 · off · 0.01 · random | 논문 근거 없음 (CLAUDE.md 금지 #4) |
| 토큰 축 pooling | **미명시** | last-token | **우리 해석** |
| `last4_mean` 의 RMSNorm | **미명시** | 앞 3개 층에 final RMSNorm 적용 | **우리 해석** — 안 하면 스케일 10배로 loss 가 clamp 포화되어 gradient 0 |

| 두 기준 일치? | ❌ (SI-SDR 0.671 dB 손해) | ✅ **일치** |
| 진짜 best 가 디스크에 남아 있나? | ❌ `ckpt_keep: 3` 이 삭제 | ✅ **보관됨** |

step 46,500 에서는 `val/loss` −9.4925 = SI-SDR 9.493 으로 **clamp 가 작동하지 않았고**(대실패 샘플 없음),
그래서 두 기준이 같은 step 을 골랐습니다. **구조적으로 해결된 것이 아니라 이번에 운이 좋았던 것**입니다 —
v3 에서는 `val/si_sdr` 기준 선정을 반드시 구현해야 합니다.

`ckpt_keep: 10` 덕분에 보관분(45,500~50,000) 중 SI-SDR 상위는 **46,500(9.493) · 48,500(9.024) · 49,500(8.734)** 로,
사후 재선정이 필요했더라도 가능한 상태입니다. v1에서 잃었던 여지를 확보했습니다.

| **order 실패는 그대로**일 것 | — | **0.622 → 0.377 dB · 혼동률 43.8% → 47.6%** | ✅ **적중, 오히려 악화** |

★ **이 실험의 가장 깔끔한 결과는 "사전 예측이 dev-50 보다 정확했다"는 것입니다.**
dev-50 은 +3.015 dB 를 시사했고 저는 이를 근거로 "예측이 크게 빗나갔다"고 잠정 기록했습니다.
test 전수 결과는 **+0.287 dB** 로, 예측한 ±0.2 dB 에 훨씬 가깝습니다. 미리 적어둔 예측이
중간 지표보다 신뢰할 만했던 사례입니다.

**예측 근거의 한계는 그대로 유효합니다.** 근거는 "v1 가중치를 `last4_mean` 으로 **강제 로드**했을 때
SI-SDR 6.14 → 6.21 dB (+0.07)" 였습니다. 이는 **`last_layer` 로 학습된 `proj` 에 다른 pooling 을 끼워 넣은
측정**이고, **처음부터 `last4_mean` 으로 학습하는 것**과는 다른 문제입니다. 전자는 "이미 학습된 표현이
얼마나 견고한가"를, 후자는 "어떤 표현이 더 학습하기 좋은가"를 재는 것입니다. 이 둘을 혼동했다는
지적은 남습니다 — 실제 차이(+0.287 dB)가 강제 로드 측정(+0.07 dB)의 **4배**이기 때문입니다.

⚠️ **확정된 것과 확정되지 않은 것을 구분합니다.**

| | 상태 |
|---|---|
| `last4_mean` 이 신호 지표를 개선한다 | ✅ 확정 (paired p=0.0054, 승률 59.9%, 평균·중앙값 동방향) |
| 개선 폭이 +0.287 dB 다 | ⚠️ **단일 시드 1회** — pooling 효과와 시드 효과가 분리되지 않음 |
| WER·spk_sim 은 오히려 나빠진다 | ✅ 확정 (0.5234 → 0.5457, 0.7166 → 0.7056), 원인도 실측 규명 |
| order 실패가 crop 때문이다 | ✅ 강화 — pooling 을 바꿔도 개선 없음. 단 crop 을 직접 바꿔본 것은 아님 |
| v2 가 v1 의 정체 구간(17,500 step)을 겪지 않은 것이 pooling 때문이다 | ❌ **알 수 없음** — 시드 효과와 구별 불가 |

> 📌 **부수적으로 확정된 것**: `best` 체크포인트 선정이 test 성능을 개선하지 못합니다(§7.5,
> p=0.886, 승률 44.4%). v1 에서 의심됐던 문제가 **선정 기준을 고친 v2 에서 더 뚜렷해졌습니다.**
> 이것은 사전 예측 항목이 아니었으므로 **예상하지 못한 발견**입니다.

### 이 실험에서 확인된 것

| 질문 | 답 |
|---|---|
| `last4_mean` 이 정상 학습되는가 | ✅ **된다.** `nan_skips` 0, 발산 없음, 50 epoch 완주 |
| RMSNorm 보정이 필요했는가 | ✅ **필수였다.** 없으면 스케일 10배 → clamp 포화 → gradient 0 (커밋 `ca9ccab`) |
| `ckpt_keep: 10` 이 효과가 있었는가 | ✅ **있었다.** 보관분 중 SI-SDR 상위 3개가 전부 살아 있어 사후 재선정 가능 |
| clamp 불일치가 해결됐는가 | ❌ **아니다.** 12회/100회 발생(최대 1.000 dB). 이번엔 best step 에서만 우연히 일치 |

### 다음 실험(v3)에 넘길 것

1. **★ `val/si_sdr` 기준 best 선정을 실제로 구현할 것.** v2 는 우연히 일치했을 뿐 clamp 불일치는 그대로입니다(§6.2).
2. **★ `segment_train` 을 14초 이상으로.** order 실패의 유일한 근본 해결책이며, `text_pooling` 보다 기대 효과가 훨씬 큽니다([v1 §7.6](../../../exp_reports/llmtse/llmtse_baseline_v1/report.md)).
3. **★ 시드 반복.** pooling 효과를 시드 효과와 분리하려면 최소 2~3 시드가 필요합니다. 지금은 n=1 입니다.
4. **`val_max_batches` 를 500 이상으로.** dev 1% 로는 best 선정도 v1↔v2 비교도 신뢰할 수 없습니다.
5. **GPU 경합을 소요 추정에 반영할 것.** 이번에 1.78배 빗나갔습니다(§5.1).

## 9. 알려진 제약

- **`text_pooling` 외 모든 미정렬 항목이 v1 그대로다** (§2.3). 이 실험은 "논문대로 전부 맞췄다"가
  아니라 **"pooling 한 항목을 논문으로 맞췄다"** 만 주장할 수 있다.
- **order 카테고리(전체의 35%)는 여전히 실패한다** — 예측대로였고 오히려 나빠졌다
  (0.622 → 0.377 dB, 혼동률 43.8% → 47.6%, §7.6). 원인은 6초 crop 이고 이번에 바꾸지 않았다.
  논문 표에 이 조건을 숨기지 말 것.
- validation 표본이 dev 의 1%(50 발화)라 **best/last 를 구분하는 능력이 사실상 없다.**
  전수 채점 확정치: v1 은 dev +2.113 dB → test **+0.181 dB**(11.7배 과대평가),
  v2 는 dev +2.226 dB → test **+0.011 dB**(**200배**). ★ v2 는 `val/loss` 와 `val/si_sdr` 이
  **일치하는** step 을 골랐는데도 그렇습니다(§7.5) — 즉 `val/si_sdr` 기준 사후 재선정으로도
  해결되지 않습니다. **표본 크기 자체를 늘려야 합니다**(dev 전체 또는 최소 500 발화).
